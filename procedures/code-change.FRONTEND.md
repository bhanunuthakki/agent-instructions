# Frontend engineering reference

Use `frontend-quality` for the user-task hypothesis, compositional restraint, reduction pass, and rendered evidence. Use the project’s existing design system and accessible primitives; for a new UI foundation, use `scaffold-design-system` after the hierarchy is known. This reference owns implementation mechanics only.

- **Prefer native browser primitives over manual JS reimplementations:** use native `position: sticky`, native scroll containers, and CSS paint order rather than JS-positioned clones, manually forwarded `wheel`/`touch` events, or `clip-path`/mask occlusion tricks, which routinely break `deltaMode` wheel scrolling, touch panning, scroll-chaining at edges, hit-testing, and `IntersectionObserver`-vs-render timing.
- **Use native semantics before ARIA:** icon-only controls need accessible names; decorative elements are hidden from assistive technology. Preserve visible `:focus-visible` treatment and use established keyboard/focus primitives rather than hand-rolled logic.
- **Target size, spacing, and mobile viewports:** use the project’s accessible target-size and spacing contract (24px pointer and 44px touch targets are starting defaults for new interfaces). Mobile input text should avoid unintended zoom (16px default), and fixed mobile layouts must use dynamic viewport units and safe-area insets.
- **Forms and state completeness:** allow paste, validate after input rather than during it, focus the first submitted error, preserve password-manager and 2FA behavior, warn on unsaved changes, give images explicit dimensions, use locale-aware date/number formatting, handle empty/loading/error states, and verify controlled inputs.
- **Animation and virtualization:** prefer `transform` and `opacity` for inexpensive animation; other properties require relevant performance evidence. Respect `prefers-reduced-motion` and measure before virtualizing.
- **Pixel-exact visual parity (`visual-parity`):** when migrating a styling system or matching two UI implementations, capture a baseline screenshot harness across component states before any code edit. Migrate shared primitives first as a blocking phase, then migrate one component per worktree owner (`separate-before-serializing-shared-state`), verifying zero pixel delta via automated image diff on the real rendered surface without modifying the baseline or harness.
