# Iteration Shortcut

Use a shortcut only when it buys a named learning or iteration outcome and the durable implementation would be disproportionate now. This procedure owns the temporary boundary; the affected data, frontend, security, product, or operations owner keeps veto authority.

## Compact contract

Record:

- intended learning or iteration outcome;
- exact shortcut and affected boundary;
- owner approval, or the authoritative instruction that pre-approves this shortcut category;
- verification, truth, and user-visible behavior that remain intact;
- impact on performance, maintenance, data, recovery, and provenance;
- expiry or cleanup trigger; and
- durable replacement or named debt location.

Ask once before a material shortcut unless its exact category is already authorized. Approval for one boundary is not a blanket waiver.

## Invariants

A shortcut never waives credential protection, authorization, destructive-action confirmation, money controls, production or external mutation authority, provenance truth, irreplaceable data integrity, or recovery for retained canonical state. Experiment on a snapshot, disposable copy, derived projection, or isolated mockup rather than the only copy of canonical data.

An isolated, non-mergeable UI mockup may use prototype-only code or CSS only when that category is pre-approved. Label it, exclude it from production imports and live state, and discard it or recompose it through production masters before implementation. Mockup approval authorizes direction, not production code.

## Exit

At the cleanup trigger, remove the shortcut or ask the owner to renew the exact boundary with updated impact evidence. Do not let repeated use silently convert a temporary compromise into architecture.
