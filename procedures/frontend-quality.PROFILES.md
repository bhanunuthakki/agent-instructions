# Interface profile seeds

Profiles are starting hypotheses for a new project, never continuing authority. Once a project
has an `## Interface` declaration and local contract, agents follow those project-owned sources.

## `dense-desktop`

For high-frequency desktop tools where scanning and repeated action dominate. Start by testing a
compact control rhythm, restrained typography, one dominant workspace, keyboard flow, immediate
mutation feedback, and a desktop primary viewport. Do not infer touch-sized desktop controls.

## `editorial-reading`

For reading, synthesis, and narrative comparison. Start with measure, hierarchy, citation clarity,
stable anchors, and progressive disclosure. Density should support comprehension rather than mimic
a dashboard.

## `touch-first`

For primarily mobile or tablet interaction. Start with reachable actions, 44px touch targets,
16px inputs, safe areas, dynamic viewport behavior, and interruption-tolerant state recovery.

## `none`

For repositories with no rendered user interface. Declare only `Profile: none`; omit the visual-only
Contract, Executable authority, Render, and Gate fields.
